# ADR-0015: The web page of a server (Mockingbird Client Webview)

Status: accepted (after 0.1.19, unreleased).

## Context
The server already speaks HTTP (ADR-0013, ADR-0014). The owner asked for a web view of the Client, named Mockingbird Client Webview: a computer without Mockingbird installed should be able to send a recording to a server, follow it, review the transcript and export it, in a browser.

## Decision
- **The server serves the page itself**, at its own address (`GET /` when the request asks for `text/html`; a program that asks for anything else still gets the plain-text overview). Three small files (`index.html`, `app.js`, `app.css`) are embedded in the program (`Web/`) and served by `WebApp` before the API. There is no library, no build step and no address outside the server. Studio and the Server edition serve it; the Client edition hosts nothing.
- **The page is open, the API is not.** The page holds nothing private, so it is served without a password. Everything it shows comes from the same API as any other client, and the API asks for the password as before. The page asks for the password in a form, sends it only in an `Authorization: Bearer` header, and keeps it in `sessionStorage` (the browser tab; closing the tab forgets it). It is never put in an address, a cookie or `localStorage`. The chosen language is kept in `localStorage`.
- **A strict policy.** Every file of the page comes with `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; media-src blob:; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`, `X-Frame-Options: DENY` and `Referrer-Policy: no-referrer` (the HTTP server adds `nosniff` and `no-store` to every answer). There is no inline script or style and no `unsafe-inline` or `unsafe-eval`. The recording is fetched with the password and played from a `blob:` address the page made.
- **Transcripts are text.** The script builds the page with DOM calls and sets text with `textContent`/text nodes. `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval` and `new Function` do not appear (a test reads the files). A transcript, a file name or an error message from the server can contain anything and is never interpreted as markup.
- **No rebinding.** A server without a password only answers `/v1/*` (except the health check) when the request is addressed to an IP address, `localhost` or the name of the computer (`Host` header, 421 `unexpected_host` otherwise). Without this a web page on another site could be made to reach a password-less server on the local network under the other site's name (DNS rebinding). With a password the server does not need to care.
- **The same pages as the Client.** *New transcription* (choose or drop a file, a language, a progress bar while it is sent), *Projects* (the recordings on the server with their stages and percentages, open or cancel), *Review* (search, the places to listen to, the regions with their source, the editor with *Use Whisper*, *Use Canary* and *Restore automatic result*, comparison and raw output, the recording with *Play region*, *Save edits* with a revision history, export as text, subtitles, Markdown, JSON with provenance, CSV or Word, strict or readable). Keys when not typing: space plays, `j` and `k` move, `1`, `2` and `3` choose a text, `e` edits.
- **The five languages.** The page asks the server for `/ui/strings.json?lang=xx`: the translations (from the program's own tables, so there is one set of words) of the texts the script uses with `t("...")`, plus the names of the languages and the stages of the work, which the API sends in English. The browser's language is the first choice; a selector changes it at once. Error messages from the API itself stay in English. A test checks that every text of the script has a translation in all four tables, and the usual unused-text check counts the script as a user of the tables.
- **Opening it.** *Open web page* in the hosting box opens the address in the default browser. On the network the address is `https://`; the certificate is the server's own, so the browser warns once and the user compares the fingerprint, as in ADR-0014. The browser then keeps the exception, which is the browser's side of the same trust.

## Limits
One recording at a time, as the server. No live updates beyond polling every 2.5 seconds. Uploads go to the server as one request (a very large recording over a poor connection starts again from the beginning). Error messages from the server are shown in English. The page needs a current browser (fetch, `XMLHttpRequest` upload progress, `blob:` audio). It does not install itself (no service worker) and does not work offline.

## Verification
`WebAppTests` run the server over a real socket: the page for a browser and the text overview for a program, the policy and the other headers on every file, the page open and the API closed, the translations for each language (exactly the texts the script uses, nothing else of the table), the host rule (a theory over names, the computer's own name with and without its domain, 421 without a password and not with one), and a read of the three files for the forbidden calls, outside addresses and the way the password is kept. The page was also driven in a browser against a real server with the real engines: wrong and right password, sending a file, the projects list, opening a transcript, editing and saving, exporting, switching the language, signing out and reloading.
